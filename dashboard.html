Question-wise requirements

Detailed assignment contents

Expand each subject to review its questions, deliverables and technical requirements.

Section A C Programming Language35 marks · Questions 1–7

Q1. Pointer Arithmetic and Dynamic Memory Management 5 marks

Dynamically allocate an array of n integers; read values; calculate sum and arithmetic mean using pointer arithmetic; find minimum and maximum; reverse the array in place using pointers; and release allocated memory. Validate the size, check allocation success, prevent leaks and invalid access, and explain reversal complexity.

Q2. Structures, Functions and Data Processing 5 marks

Create a Student structure containing roll number, name, three subject marks, total and percentage. Implement functions to accept multiple records, calculate totals and percentages, sort by total in descending order, search by roll number and display the highest scorer. Handle duplicate roll numbers and invalid marks.

Q3. Linked Lists and Dynamic Data Structures 5 marks

Implement a singly linked list with insertion at beginning/end/specified position, deletion by value, searching, iterative reversal, display and freeing all nodes. Explain array versus linked-list allocation and state complexity for head insertion, search and reversal. Handle empty lists, invalid positions, missing values and allocation failures.

Q4. File Handling and Persistent Records 5 marks

Build a product inventory program storing ID, name, quantity and unit price. Support add, list, search by ID, quantity update and total inventory valuation. Handle missing/unreadable files, persist records between runs, select suitable file modes and document the storage format.

Q5. Bitwise Operations and Integer Representation 5 marks

Accept an unsigned integer; display its bits at a clearly defined width; set, clear, toggle and test a selected bit; and count set bits. Use bitwise operators, explain masks, validate bit positions, avoid undefined shifts and state whether positions are zero-based.

Q6. Debugging, Undefined Behaviour and Code Analysis 5 marks

Analyse the supplied C program: identify memory-safety defects, explain the incorrect loop boundary and use-after-free, rewrite it safely, and describe how compiler warnings and a memory-safety diagnostic tool help. Distinguish intended behaviour from behaviour guaranteed by the C language.

Q7. Algorithmic Problem Solving 5 marks

Write a function-based palindrome checker that ignores case and non-alphanumeric characters. It must handle empty input and spaces safely, use no third-party string library, and explain the algorithm, time complexity and auxiliary-space complexity.

Section B Linux and Bash25 marks · Questions 8–12

Q8. Filesystem Navigation and Permissions 5 marks

Show the working directory; create final_assignment/ with c_programs/, python_programs/, scripts/, data/ and reports/; create a root README; copy and rename a source file; display file details; and set owner read/write with other users read-only permissions. Explain absolute/relative paths and r, w, x. Include genuine terminal evidence.

Q9. Process Management and Redirection 5 marks

Explain PID and PPID; list processes and identify one by name; run a harmless background process and inspect it; redirect stdout and stderr separately; use a pipeline to filter and count lines; and explain >, >>, 2> and |. Do not terminate system-critical processes.

Q10. Bash Automation 5 marks

Write executable run_tests.sh to validate a source directory, find C files, compile each separately with GCC warnings, store executables in a designated output directory, log success/failure and return nonzero if any compilation fails. Quote variables, support filenames with spaces, use meaningful exit codes, shebang and comments; demonstrate at least three C files including one deliberate error.

Q11. Linux Diagnostic and Troubleshooting Report 5 marks

Record commands and observed output for OS/kernel details, disk space, memory, current user/groups, network interfaces/IP configuration and a connectivity test where possible. Explain what each command reveals and one practical use. Never invent output or publish secrets.

Q12. Shell-Based Data Processing 5 marks

Create at least 20 fictional student records in a consistent format. Write a Bash script to validate the file, count records, find highest/lowest marks, calculate average, list students scoring at least 75 and write a formatted report. Handle malformed records, document validation rules and explain the pipeline.

Section C Python Programming25 marks · Questions 13–17

Q13. Functions, Collections and Data Validation 5 marks

Accept student records and calculate totals, percentages, class average, highest/lowest scores, count above average and ranking with a documented tie-break rule. Use lists, dictionaries, functions and loops; validate marks, handle empty data and separate collection, calculations and display.

Q14. File Processing and Exception Handling 5 marks

Read a CSV with student IDs, names and three subject marks. Detect missing fields and invalid numbers, calculate totals/averages, write valid records to a new CSV and invalid rows to an error report. Handle missing files and access errors; never modify the original input. Use Python's standard CSV tools.

Q15. Object-Oriented Programming 5 marks

Design a BankAccount class with holder name, account number, balance, deposit, withdrawal and balance inquiry. Demonstrate at least three test cases including an invalid transaction. Reject non-positive amounts, prevent overdrafts and encapsulate state. Explain class versus instance and operation-level validation.

Q16. Recursion, Iteration and Complexity 5 marks

Implement GCD of two non-negative integers using iterative and recursive Euclidean algorithms. Test normal and boundary cases; use GCD(0,n)=n for positive n; document GCD(0,0); compare time, auxiliary space and stack use.

Q17. Automated Testing and Debugging 5 marks

Create a prime-checking Python function and a separate test module using unittest. Test negatives, 0, 1, 2, small primes, composites, a relatively large prime and invalid types under a documented contract. Explain boundary-value testing and include the test command and actual output.

Section D Integrated Mini-Project15 marks · Question 18

Q18. Student Performance Analytics and Report Generator 15 marks

Develop an integrated student-performance system in which C, Linux/Bash and Python each have a distinct documented role and communicate through documented input/output files.

  • Part A — C data-entry utility: accept student ID, name and marks in three subjects; validate input and write valid records to a documented CSV.
  • Part B — Bash execution pipeline: verify files/directories, compile C, run it with sample input, invoke Python analysis, store logs/reports and return an appropriate status on failure.
  • Part C — Python analytics engine: read CSV; calculate totals, averages, rankings and subject statistics; identify students needing support using a documented threshold; write summary and ranked CSV; handle malformed records safely.
  • Part D — Documentation and verification: provide README, project tree, at least five meaningful tests, genuine end-to-end evidence, design choices, limitations and improvements.

Minimum standards: Linux execution, warning-free C compilation under chosen flags, Python standard library unless justified, demonstrated validation/error handling, fictional data only, and distinct documented component responsibilities. Unrelated files merely placed in one folder do not meet the integration requirement.

Submission and evaluation

Rules, deliverables & marking

Submission requirements

  • Individual practical assignment; each student must explain and demonstrate their work.
  • Submit one archive named Final_Assignment_RollNumber.zip, plus any separately requested declaration or cover sheet.
  • Keep source files readable and appropriately named; include useful comments.
  • Validate inputs and handle expected errors. Compile C with suitable warnings; use Python 3.
  • Include genuine terminal output/screenshots. Use fictional sample records only; never include real student personal data or secrets.
  • Retain a backup until marks are finalised. Disclose substantial external code or AI assistance under institutional policy.

Recommended project structure

Final_Assignment_RollNumber/
├── README.md
├── c_programs/
├── linux/
├── python_programs/
├── integrated_project/
│   ├── src/  scripts/
│   ├── data/ reports/
├── tests/
└── evidence/
    ├── compilation/  linux/
    ├── python_tests/ integration/

Identify every numbered question clearly. Do not include binaries, virtual environments or generated caches unless requested.

Mark distribution

  • C Programming — 35 marks
  • Linux & Bash — 25 marks
  • Python Programming — 25 marks
  • Integrated Project — 15 marks
  • Total — 100 marks

Overall rubric: correctness 30%, implementation/design 25%, error handling/reliability 15%, testing/verification 15%, documentation/code quality 10%, explanation/originality 5%.

Suggested 16-day work plan

  • Days 1–3: C foundations, pointers, structures, linked lists and memory safety.
  • Days 4–5: C files, bitwise operations, debugging and algorithms.
  • Days 6–8: Linux/Bash questions 8–12.
  • Days 9–11: Python questions 13–17.
  • Days 12–15: integrated project, tests and reports.
  • Day 16: clean-environment verification and viva preparation.

Viva voce preparation

Be prepared to explain use-after-free, arrays versus linked lists, stack versus heap, permissions and ownership, pipelines, exit statuses, Python lists versus dictionaries, malformed CSV handling, recursion versus iteration, unit testing, integration failure reporting and scaling to large datasets.

Academic integrity & technical rules

Work must be individual and reproducible. No fabricated evidence. Use safe programming practices, document environment/tool versions and be ready to explain every function, script, algorithm and design decision. Late penalties and promotion decisions follow published institutional regulations.
